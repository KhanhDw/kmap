# M4 — Tài khoản và phân quyền (tuần 2, ngày 7–8)

Đọc trước: `docs/DECISIONS.md` (D-10, D-11, D-16), `docs/RULES.md` mục 3, 4.

## Làm
- `POST /api/v1/auth/register` (email, password, display_name), `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout`, `GET /auth/me`. Cơ chế token và cookie đúng D-11.
- Email chuẩn hóa chữ thường; mật khẩu tối thiểu 10 ký tự; argon2.
- Dependency `get_current_user` đọc user từ DB mỗi request (ban và đổi role có hiệu lực ngay). Dependency `require_role("moderator" | "admin")`.
- Rate limit đăng ký/đăng nhập 10 lần/phút/IP (D-10). Kiểm chứng IP thật được lấy từ `X-Forwarded-For` khi đi qua Caddy.
- Bảng `refresh_tokens`: lưu băm; xoay token mỗi lần refresh; thu hồi khi logout hoặc ban.
- `scripts/seed_admin.py` (và `make seed-admin`) tạo admin đầu tiên từ biến môi trường; chạy lại không tạo trùng.
- Frontend: `/login`, `/register` (nói rõ tên hiển thị sẽ công khai), lưu access token trong bộ nhớ, tự refresh khi gặp 401, đăng xuất. Nút/menu tài khoản trên bản đồ. Route `/admin/*` chỉ cho moderator/admin (người khác thấy trang 403 tiếng Việt). Layout admin chỉ là khung trống.
- **E2E khung (Playwright):** đăng ký → đăng xuất → đăng nhập → thấy tên mình; user thường vào `/admin` bị chặn; admin vào được `/admin`.

## Không làm
Quên mật khẩu, xác thực email, đổi mật khẩu tự phục vụ (admin đặt lại ở M6).

## Nghiệm thu
Test tự động (pytest) cho:
- [ ] Đăng ký trùng email (kể cả khác chữ hoa/thường) → 409.
- [ ] Sai mật khẩu → 401; user bị ban → `banned`.
- [ ] Access token hết hạn → 401; refresh còn hạn đổi được token mới; token cũ bị thu hồi sau khi xoay; refresh sau logout → 401.
- [ ] User thường gọi endpoint admin → 403; chưa đăng nhập → 401.
- [ ] Ban user giữa chừng: request kế tiếp bằng access token cũ bị từ chối.
- [ ] Rate limit: lần thứ 11 trong phút → 429 `rate_limited`.
- [ ] Mật khẩu không bao giờ xuất hiện trong log và response.
- [ ] `make e2e` xanh với kịch bản khung ở trên.
